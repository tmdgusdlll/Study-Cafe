# 카페 좌석 실시간 점유 설계

## 개요

로그인한 사용자가 카페 장면의 빈자리를 골라 앉고, 다른 사용자가 어디에 앉아 있는지 실시간으로 본다.
지금은 내 캐릭터가 창가 가운데 자리에 고정되어 있고, 다른 손님은 장식용 고정 인물이다.

- 작성일: 2026-10-04
- 관련 레포: `Study-Cafe/backend`(이 문서) + `Study-Cafe/frontend`
- 배포: 프론트 Vercel / Spring 백엔드 Render(서버 1대) / DB Supabase PostgreSQL

---

## 1. 확정한 규칙

| 항목 | 결정 |
|---|---|
| 카페 수 | 1개 |
| 좌석 수 | 10석, 모두 사용자용 |
| NPC | 좌석을 쓰지 않는다. 카운터 바리스타가 NPC 역할(대화 기능은 이번 범위 밖) |
| 점유 시점 | 홈 화면에서 자리를 고르면 앉고, 카페에 머무는 동안 유지(공부 여부와 무관) |
| 비우는 시점 | 해당 회원의 마지막 WebSocket 연결이 끊기고 **30초** 동안 재연결이 없을 때. 로그아웃도 연결 종료로 처리 |
| 오래 비운 자리 | 별도 규칙 없음. 탭이 열려 있으면 계속 앉아 있는 것으로 본다 |
| 만석 | 구경 모드. 장면과 손님은 보이지만 앉을 수 없고 공부(주문)도 시작할 수 없다 |
| 회원당 자리 | 1개. 앉은 상태에서 다른 빈자리를 고르면 이동 |
| 다른 사용자 표시 | 캐릭터 + 닉네임(항상 표시). 캐릭터를 누르면 정보 카드 |
| 정보 카드 | 닉네임, 공부 상태(공부 중 / 쉬는 중), 앉은 지 얼마나 |
| 공부 상태 기준 | 타이머 `running`만 "공부 중", 그 외(대기·일시정지·목표 달성)는 "쉬는 중" |

## 2. 단계

| 단계 | 레포 | 내용 | 완료 기준 |
|---|---|---|---|
| 1. 로그인 실제 연동 | frontend | `src/api/auth.ts`의 목을 실제 API 호출로 교체(회원가입·로그인·내 정보). 포인트·세션은 목 유지 | 실제 서버로 가입·로그인 후 홈에 닉네임 표시 |
| 2. 백엔드 좌석 | backend | WebSocket(STOMP) 추가, JWT 연결 인증, 메모리 좌석 저장소, 30초 유예 | 아래 5절 백엔드 테스트 통과 |
| 3. 프론트 좌석 | frontend | 장면 10석, 자리 선택, 다른 사용자 표시, 정보 카드, 구경 모드 | 브라우저 2개로 서로의 자리가 실시간 반영 |

단계 1이 먼저 필요한 이유: WebSocket 연결을 실제 백엔드 JWT로 인증하므로, 프론트가 실제 토큰을 갖고 있어야 한다.
단계마다 별도 커밋·PR.

## 3. 백엔드 (단계 2)

### 의존성

`spring-boot-starter-websocket` 추가. 외부 메시지 브로커 없이 Spring 내장 simple broker 사용.

### 패키지

새 도메인 `com.studycafe.domain.cafe` (워크로그의 "cafe(배경/좌석) 도메인"에 해당)

| 클래스 | 역할 |
|---|---|
| `global/config/WebSocketConfig` | `/ws` 엔드포인트, `/app` 앱 prefix, `/topic`·`/queue` 브로커, `/user` prefix |
| `infra/jwt/StompAuthChannelInterceptor` | CONNECT 프레임의 `Authorization: Bearer <토큰>`을 `JwtProvider`로 검증해 Principal(회원 ID) 설정. 실패 시 연결 거부 |
| `domain/cafe/SeatRegistry` | 좌석 상태 보관과 규칙(앉기·이동·비우기). 아래 "좌석 저장소" 참고 |
| `domain/cafe/SeatPresenceListener` | 연결·연결 종료 이벤트(`SessionConnectedEvent`, `SessionDisconnectEvent`)로 회원별 연결 수를 세고 30초 유예 예약·취소 |
| `domain/cafe/controller/CafeSeatController` | STOMP 메시지 처리와 브로드캐스트 |
| `domain/cafe/dto/*` | `SeatView`, `TakeSeatRequest`, `StatusRequest`, `SeatError` |

### 좌석 저장소 (`SeatRegistry`)

- 좌석 ID는 `0`~`9` 고정. 범위 밖이면 `INVALID_SEAT`
- 좌석별 상태: `memberId`, `nickname`, `sittingSince`, `studying`
- 앉기는 원자적으로 처리해 같은 자리를 동시에 눌러도 한 명만 앉는다. 이미 다른 회원이 앉은 자리면 `SEAT_TAKEN`
- 이미 앉아 있는 회원이 다른 자리를 고르면 기존 자리를 비우고 이동한다. 이때 `sittingSince`는 유지
- 닉네임은 앉을 때 `MemberRepository`에서 조회해 넣는다
- 서버 재시작 시 좌석은 모두 사라진다. 재시작하면 연결도 끊기므로 사용자가 다시 접속해 앉으면 된다
- 이 클래스만 좌석 데이터를 직접 다룬다. 서버를 여러 대로 늘릴 때 이 클래스의 저장 방식만 Redis로 바꾼다 (6절)

### 연결 수와 30초 유예

- 회원별 열린 연결을 STOMP 세션 ID 집합으로 센다(탭 여러 개 대응). Spring은 같은 세션의 연결 종료 이벤트를 두 번 보낼 수 있으므로 ID 집합으로 중복을 무시한다
- STOMP 하트비트(10초)로 노트북 덮기·네트워크 끊김처럼 연결이 조용히 죽은 경우도 연결 종료로 감지한다
- 연결 수가 0이 되면 30초 뒤 좌석 비우기를 예약한다. 그 안에 같은 회원이 다시 연결하면 예약 취소
- 예약이 실행되어 좌석이 비면 전체 좌석을 브로드캐스트

### 메시지 규격

| 방향 | 주소 | 내용 |
|---|---|---|
| 구독(1회 응답) | `/app/cafe/seats` | 현재 좌석 전체 (`@SubscribeMapping`) |
| 구독(변경마다) | `/topic/cafe/seats` | 좌석 전체 |
| 보내기 | `/app/cafe/seat.take` | `{ "seatId": 3 }` 앉기·이동 |
| 보내기 | `/app/cafe/status` | `{ "studying": true }` 공부 상태 변경 (앉아 있지 않으면 무시) |
| 개인 수신 | `/user/queue/errors` | `{ "code": "SEAT_TAKEN" }` 또는 `INVALID_SEAT` |

좌석 전체 형식(빈자리는 `occupant: null`):

```json
[
  { "seatId": 0, "occupant": { "memberId": 7, "nickname": "테스트어드민", "sittingSince": "2026-10-04T14:05:00Z", "studying": true } },
  { "seatId": 1, "occupant": null }
]
```

- 변경분이 아니라 항상 10개 전체를 보낸다. 크기가 작고 클라이언트 상태가 어긋날 일이 없다
- 공부 상태는 화면 표시 전용이라 클라이언트 값을 그대로 쓴다. 포인트 적립과 무관

### 보안 설정

- `SecurityConfig`에서 `/ws/**` HTTP 핸드셰이크는 허용하고, 인증은 STOMP CONNECT 단계에서 인터셉터가 한다
- CORS 허용 출처는 기존 설정(로컬 `http://localhost:5173`, 운영 Vercel 도메인)을 WebSocket 엔드포인트에도 적용

## 4. 프론트 (단계 1, 3)

### 단계 1: 로그인 실제 연동

- `src/api/auth.ts`의 `mockSignup`·`mockLogin`·`mockGetMe`를 `fetch` 호출로 교체. 응답 모양(`ApiResponse`)은 이미 백엔드와 같게 맞춰 둠
- API 주소는 환경 변수 `VITE_API_URL`
- 포인트(`points.ts`)와 공부 세션은 이번에는 목 유지

### 단계 3: 좌석

- STOMP 클라이언트 라이브러리 `@stomp/stompjs` 추가(브라우저 기본 WebSocket 사용, SockJS 없음)
- 좌석 연결·구독·전송은 훅 하나(`useCafeSeats`)에 모은다. 좌석 전체를 상태로 들고, 파생 값(내 자리, 만석 여부, 고를 수 있는 자리)은 순수 함수(`lib/seats.ts`)로 계산
- 타이머 상태가 `running`으로 바뀌거나 벗어날 때 `/app/cafe/status` 전송

### 화면 동작

- **들어왔을 때 빈자리 있음**: 빈 의자가 은은하게 강조되고 "앉을 자리를 골라주세요" 안내. 의자를 누르면 앉는다. 앉기 전까지 주문 패널은 "먼저 자리를 골라주세요"로 비활성
- **만석(구경 모드)**: "지금은 만석이에요. 자리가 나면 바로 앉을 수 있어요" 안내. 주문 비활성. 누가 일어나면 그 의자가 바로 눌러지는 상태로 바뀐다(알림음·토스트 없음)
- **앉은 뒤**: 다른 빈 의자를 누르면 이동. 별도 "일어나기" 버튼 없음
- **새로고침**: 30초 유예 안에 다시 연결되므로 같은 자리에 그대로 앉아 있다
- **자리를 빼앗긴 경우**(`SEAT_TAKEN`): "방금 다른 분이 앉았어요" 안내. 이미 앉아 있던 경우 원래 자리에 그대로, 아니면 자리 고르는 상태로 남는다
- **연결 끊김**: 재연결을 시도하는 동안 "연결 중…" 표시

### 장면

- 17석을 10석으로: 창가 바 스툴 4, 부스 2, 둥근 테이블 2개(의자 4). 정확한 위치는 구현 중 스크린샷으로 조정
- 좌석 ID `0`~`9`와 장면 좌표의 대응표를 프론트 상수로 둔다. 백엔드는 ID만 안다
- 고정된 내 캐릭터(`Me`)를 없애고 좌석 데이터대로 캐릭터를 그린다. 캐릭터 모양은 같고 옷 색만 회원 ID로 결정. 내 캐릭터에는 앰버색 작은 표시
- 닉네임은 캐릭터 머리 위에 항상 표시
- 카운터 앞 "주문하는 손님"(장식용)은 실제 사용자와 헷갈리므로 제거. 바리스타 2명은 유지(향후 NPC)
- 색과 모션은 `DESIGN.md`를 따른다

### 정보 카드

캐릭터를 누르면 뜨는 작은 카드: 닉네임, "공부 중" / "쉬는 중", "40분째 앉아 있어요".
"대화하기" 버튼 자리만 비워 둔다(이번 범위 밖).

## 5. 테스트

**백엔드**
- `SeatRegistry` 단위 테스트: 빈자리 앉기, 이미 찬 자리(`SEAT_TAKEN`), 범위 밖 좌석(`INVALID_SEAT`), 이동 시 기존 자리 비움과 `sittingSince` 유지, 만석에서 앉기 실패
- 연결 수·유예 테스트: 마지막 연결 종료 후 30초 뒤 비움, 30초 안 재연결 시 유지, 탭 2개 중 1개만 닫으면 유지 (시간은 주입해서 테스트에서 조절)
- STOMP 통합 테스트: 토큰 없이·잘못된 토큰으로 연결 거부, 앉으면 다른 구독자가 브로드캐스트 수신

**프론트**
- `lib/seats.check.ts`: 내 자리, 만석 여부, 고를 수 있는 자리 계산
- Playwright로 브라우저 컨텍스트 2개(서로 다른 계정)를 띄워 앉기·이동·실시간 반영·새로고침 유지 확인

## 6. 확장: 서버를 여러 대로 늘릴 때 (Redis)

지금 설계는 **Spring 서버 1대**를 전제로 한다. 여러 대로 늘리면 두 가지가 깨진다.

1. **좌석 데이터**: 서버마다 메모리가 따로라서, A 서버에 붙은 사용자와 B 서버에 붙은 사용자가 서로 다른 좌석표를 본다
2. **브로드캐스트**: 내장 simple broker는 자기 서버에 연결된 클라이언트에게만 보낸다

바꿀 곳:

| 무엇 | 지금 | 바꿀 것 |
|---|---|---|
| 좌석 데이터 | `SeatRegistry` 안의 메모리 맵 | Redis 해시. 앉기는 Redis에서 원자적으로 처리(빈자리일 때만 설정) |
| 회원별 연결 수·30초 유예 | 서버 메모리 카운터 + 예약 작업 | Redis 카운터 + 만료 시간(TTL) 키 |
| 브로드캐스트 | 내장 simple broker | Redis Pub/Sub로 서버 간 전달, 또는 외부 STOMP 브로커(RabbitMQ) 릴레이 |

`SeatRegistry`와 `SeatPresenceListener`만 좌석·연결 데이터를 다루도록 경계를 두었으므로, 컨트롤러·메시지 규격·프론트는 그대로 둔다.

## 8. 배포 참고 (Supabase PostgreSQL)

- 좌석은 DB를 쓰지 않으므로 Supabase와 무관. 회원·포인트·세션 같은 영구 데이터만 Supabase에 저장
- JPA 연결은 직접 연결(5432) 또는 세션 풀러를 쓴다. 트랜잭션 풀러(6543)는 prepared statement와 충돌할 수 있다
- 무료 플랜은 일정 기간 사용이 없으면 DB가 일시 정지된다
- Render 무료 인스턴스가 잠들면 WebSocket 연결도 끊긴다. 깨어나면 클라이언트가 재연결하고 사용자가 다시 앉는다
